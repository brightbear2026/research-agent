# 研究质量记录与补研协议

本协议复用六阶段状态机和 schema v2，不新增审批点或无限循环。三种宿主均通过 `CLAUDE.md` 读取；章节研究者写各自 `.meta.json`，避免并发改写共享索引。

## 从读者问题开始

研究卡先定义 3–6 个核心问题、稳定 ID 和可检查的验收条件。考虑机制、采用者/成本、竞争方案、失败案例等适用视角；不机械凑视角，不预设结论。沿用启动与大纲中已确定的问题，新增或移除问题时说明范围变化，不能写完报告后只登记已经回答的问题。

每轮检索先查尚未回答且会改变核心结论的问题。先广搜定位原始材料，再根据口径差异或反例窄搜。记录实际查询、来源和结果，保留有效发现与原始出处；不要保存冗长的内部推理。

## 可选 schema v2 扩展

新研究应填写这些记录；旧 v2 元数据缺省时仍可处理，但会给出覆盖缺口。字段一旦填写，格式和 ID 关系必须通过校验。

在章节顶层添加以下结构。示例的 E1、S1 须替换为本章实际 ID，不能原样当作真实证据使用：

```json
{
  "research_questions": [
    {
      "question_id": "Q1",
      "question": "目标市场的规模和统计口径是什么？",
      "status": "partial",
      "evidence_ids": ["E1"],
      "gap_reason": "只有机构估计，尚未找到独立统计。"
    }
  ],
  "search_log": [
    {
      "question_id": "Q1",
      "query": "实际使用的检索关键词",
      "intent": "counter",
      "outcome": "no_new_evidence",
      "source_ids": [],
      "reason": "实际检索结果摘要，以及缺口或后续检索方向。"
    }
  ]
}
```

- 问题状态：`answered / partial / unanswered`。已回答或部分回答须关联证据；未完全回答须说明 `gap_reason`。这表示研究者的记录，工具不自动判断答案是否正确。
- 检索用途：`support / counter / background`。
- 检索结果：`new_evidence / no_new_evidence / blocked`。发现新证据须关联来源；受阻检索不能计作已完成反向检查。没有找到反证是有效记录，不代表原假设已被证明。
- `reason` 只写简短、可审计的结果摘要和后续方向。不得补写没有实际执行过的检索。

阶段三编译进大纲的检索任务，分章登记为 `search_tasks`（类型化检索，把"主动搜反方"从自觉变成有账本的任务）：

```json
{
  "search_tasks": [
    {
      "task_id": "T1",
      "type": "refute",
      "focus": "寻找 XX 方案在生产环境的失败案例或负评估",
      "status": "done",
      "result": "找到 2 起生产事故披露，登记为 E3；规模化场景的负面证据未找到",
      "evidence_ids": ["E3"]
    },
    {
      "task_id": "T2",
      "type": "pin",
      "focus": "锁定提出 XX 指标的一手论文（不引二手转述）",
      "status": "done",
      "result": "原始论文为 S5；两篇博客转述口径与原文不一致",
      "source_ids": ["S5"]
    }
  ]
}
```

- 任务类型：`explore`（章节探索）/ `refute`（反方与局限检索）/ `pin`（必引原文定向锁定——回到提出方法、数据集或指标的一手来源，不引转述）。
- 状态流转 `planned → done / partial / open`；`done` 须在 `result` 一句话记录结果（找到什么 / 确认没有），`pin` 完成还须关联 `source_ids`。确实无反证是合法结果，记录查询与结论即可，不得虚构反证。
- 未完成的 `refute` 任务会在终检给出 `refute_task_open` 补研建议；反方结论应汇入争议矩阵。

对核心结论可在 `claims[].priority` / `chapter_conclusion.priority` 标 `P0 / P1`（可选）。标 `P0` = 研究者承诺该结论必须有一级/权威（A/B 级）来源背书，终检将强制核验；不达标须补来源或降级为 P1。P0 是自标注，工具不判断其成色，只核验背书。**引用覆盖率为过程指标：不设"必须引用收集文献的百分之多少"之类硬性配额**，防止为凑数引用低质来源。

在每条 `data_points` 中可添加 `provenance` 数组，每个来源记录一次：

```json
{
  "provenance": [
    {
      "source_id": "S1",
      "locator": "第 12 页，表 3，目标市场行",
      "excerpt": "实际读取的必要短摘录；此示例不是证据。",
      "access_date": "2026-09-10"
    }
  ]
}
```

`source_id` 必须属于该条证据；`locator` 使用真实页码、章节、表格或可定位网页标题，不猜页码。`excerpt` 只保留支撑声明所需的短片段，遵守来源版权限制；一个来源的英文直接引语合计最多 25 词。工具检查记录完整性，不核验摘录真伪。多个来源支持同一证据时，每个来源分别登记，不能把甲来源的摘录套给乙来源。

来源为转载时，在 `sources` 的对应对象增加经核实的 `origin_url`。同文 URL、原始出处和生产者分组构成合并关系；独立计数取合并后的组数，不能靠改机构名或换跟踪参数提高。无信息的未知来源不计数。工具不能自动识别未登记的转载关系；独立论文共用一个托管域时需填写经核实的生产者/分组，不能凭域名断言独立性。

## 终检与补研

按原流程执行 `tools/qc.py --strict`，会自动重验章节元数据并生成 `data/quality_scorecard.json`，不需要额外命令。结构错误、悬空 ID 及独立来源不足仍属核心问题。同一证据同时标为支撑和反对时提示人工复核其对条件性结论的不同作用；不自动删除反方证据，也不一律阻断。旧记录缺少扩展字段属于 advisory，不增加历史课题迁移负担。

诊断列出八项覆盖指标，每项保留分子、分母与比例：

| 指标 | 检查什么 | 不代表什么 |
|---|---|---|
| question_plan_coverage | 有问题登记的章节 / 全部章节 | 问题设计已经充分 |
| question_answer_coverage | 标为已回答的问题 / 已登记问题 | 正文确实完整回答了全部需求 |
| claim_support_coverage | 有支撑证据关联的声明 / 全部声明 | 引用内容真的支持声明 |
| evidence_provenance_coverage | 每个来源都有原文位置和短摘录的证据 / 全部证据 | 摘录已被独立核验 |
| counter_search_coverage | 有非受阻反向查询的问题 / 已登记问题 | 原假设不存在反例 |
| search_task_completion | 已完成的类型化检索任务 / 全部任务 | 检索质量足够 |
| refute_task_coverage | 已完成的反方检索任务 / 全部反方任务 | 反方证据已穷尽 |
| p0_ab_support_coverage | 有 A/B 级来源背书的 P0 声明 / 全部 P0 声明 | P0 的圈定恰当 |

没有分母时比例为 `null`，不能解读为满分。须把问题计划覆盖与答案覆盖一起看，避免忽略未登记问题的章节。工具不计算综合质量分，也不把这些比例称为事实正确率。`findings` 提供具体章节、问题/证据 ID 和补研建议；摘要归入 `qc_debt.json` 的 `research_quality` 类别。

优先修复影响核心答案的来源缺失与矛盾，再补回答不完整的问题，最后处理次要背景。不因每条 advisory 重新启动整个课题。沿用连续 3 轮无新进展及章节最大尝试次数的既有熔断；预算耗尽则保留资料缺口。编辑阶段只能调整已证实内容，新增证据需返回研究阶段后重新组装、冻结声明账本及核验。

## 语义验收

交付前抽查核心结论：打开原文，确认引用是否支持这句话、数字口径是否一致、反方证据是否被保留、问题是否直接回答、建议是否由证据推出。网址可访问或存在归档，只能证明材料的可访问性/历史存在性，不能证明其支持论断；不存在归档也不能直接判定来源为伪造。

比较版本质量时使用同一批固定题目、来源截止日期和研究预算，保存报告及逐项评语；以信息覆盖、分析深度、指令遵循、可读性和引用支撑分别比较。自动结构检查与人工/语义评估分开报告，不把测试通过率当作研究质量提升百分比。对本轮借鉴项目的调查及实施取舍见 `docs/research-quality-review-2026-09-10.md`。
