# deep-research 技能

本技能是「深度研究」流程的入口。推荐用 `/deep-research <课题> depth=快速|标准|深度 mode=常规|计划|执行` 触发。模式规则的事实源是 `config/workflow_modes.yaml`。

## 何时使用
用户要求就某课题做系统、广泛、深入、可验证的研究，并产出双格式报告时。

## 模式
- **常规**：阶段一、二、三各做一次内容确认。
- **计划**：公开第三方来源默认访问；阶段一、二不中断；阶段三大纲完成后只询问一次是否修改，然后停止在执行前。
- **执行**：目标明确后连续完成六阶段，工作流不设置确认点；外部阻碍按有限重试、替代来源和资料缺口规则处理。

## 流程
1. **启动**：课题定义/边界、≥15 研究问题、中英文关键词矩阵、搜索策略。
2. **广泛调研**：六维搜索 + 证据库脚手架 + 发现/争议/缺口。
3. **大纲**：基于调研生成论证地图和三级大纲。
4. **分章深研**：每章写研究卡，**派 `researcher` 子代理**执行（独立维度并行）。
5. **组装与总编辑**：v2 元数据校验与原子聚合 → Diagram Design 静态源校验 → 声明账本 → 受限总编辑。
6. **交付**：真实截图 + Diagram Design PNG 导出 → HTML → 证据库 → 严格 QC → README。

## 红线（见 CLAUDE.md）
不编造任何来源/数据/观点/截图；无法确认写「暂未找到可靠公开来源」；区分事实/观点/判断；关键数值 ≥2 独立来源；截图必须真实（失败落占位，禁止伪造）；Diagram Design 图必须标为根据公开资料整理并关联来源/结论；引用/链接/图片以 `qc.py` 全绿为准。
